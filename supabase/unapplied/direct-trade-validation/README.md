# CODEX-53 — Direct-trade validation correction

Prepared October 21, 2026. Not installed. Current production direct trades bypass the existing five-minute received-Pokémon trade cooldown and do not recheck species tradability at final confirmation. This was reproduced with exact hosted function definitions and fictional local rows; no hosted trade or protected-account action was performed.

GTS listing/offer triggers already reject a catch with a future trade_locked_until. private.mark_trade_receive sets that timestamp to now()+5 minutes. Direct-trade create/set/confirm currently lack that check. Creation and offer selection check species.tradable, but confirmation does not, so changing that setting between offer and confirmation can still allow the swap. These are validation gaps, not a claim that unauthorized trainers can access another person's trade.

The concrete correction changes only three existing function bodies: play_direct_trade_create(text,uuid), play_direct_trade_set(uuid,uuid), and play_direct_trade_confirm(uuid). Create/set reject a currently cooling-down offered Pokémon; confirmation rechecks both participants' cooldowns and current species tradability after obtaining the existing catch row locks and before ownership changes/rewards. Existing ownership, both-party consent, expiry, favorite/lock protections, last-copy trading permission, costs/rewards and five-minute duration remain. No new timer, permissions, account, scheduler or schema is introduced.
